## 2. What ACP v1 actually guarantees

The official pages at `agentclientprotocol.com/protocol/v1/` correspond to the pinned reference source below.

- Stdio messages are UTF-8 JSON-RPC, one newline-delimited message per line. Stdout is protocol-only. Logs belong on stderr. [Transport](https://agentclientprotocol.com/protocol/v1/transports), [pinned source](https://github.com/agentclientprotocol/agent-client-protocol/blob/1c0fe8dd680aa6de119b2136a7e5495075baf257/docs/protocol/v1/transports.mdx#L6-L27).
- Initialize before creating a session. Negotiate the integer major protocol version. Omitted capabilities mean unsupported. Baseline agent methods are `session/new`, `session/prompt`, `session/cancel`, and `session/update`; filesystem, terminals, session loading, and other capabilities are not implicit. [Initialization](https://agentclientprotocol.com/protocol/v1/initialization), [pinned source](https://github.com/agentclientprotocol/agent-client-protocol/blob/1c0fe8dd680aa6de119b2136a7e5495075baf257/docs/protocol/v1/initialization.mdx).
- Tool calls have stable `toolCallId`, lifecycle `pending` / `in_progress` / `completed` / `failed`, and optional input/output/content. `tool_call_update` is a **patch**, not a replacement; fields not changed need not be included. The specification calls `completed` success and `failed` failure. It does **not** promise every agent maps a shell's nonzero exit correctly. [Tool calls](https://agentclientprotocol.com/protocol/v1/tool-calls), [source](https://github.com/agentclientprotocol/agent-client-protocol/blob/1c0fe8dd680aa6de119b2136a7e5495075baf257/docs/protocol/v1/tool-calls.mdx#L100-L252).
- Permission is optional: an agent **may** call `session/request_permission`. The client selects an **offered** option ID or returns `{"outcome":{"outcome":"cancelled"}}`. Auto-allow or auto-reject is permitted by client policy. When sending `session/cancel`, the client **must** settle **all pending permission requests** as cancelled; it cannot wait indefinitely for the agent to cancel those requests. [Tool permission source](https://github.com/agentclientprotocol/agent-client-protocol/blob/1c0fe8dd680aa6de119b2136a7e5495075baf257/docs/protocol/v1/tool-calls.mdx#L133-L210).
- `session/cancel` is a **notification**, not an ACK request. Agent must abort ongoing operations, flush pending updates, then answer the **original prompt request** with `stopReason: "cancelled"`. Updates after cancellation are allowed **before** that prompt response. Accept late tool patches. A protocol response is still not an OS process-tree proof. [Prompt-turn cancellation](https://agentclientprotocol.com/protocol/v1/prompt-turn#cancellation), [source](https://github.com/agentclientprotocol/agent-client-protocol/blob/1c0fe8dd680aa6de119b2136a7e5495075baf257/docs/protocol/v1/prompt-turn.mdx#L549-L582).
- Generic `$/cancel_request` support is optional and distinct from prompt-turn cancellation. Cascading cancellation to terminal requests is optional, not automatic. [Cancellation](https://agentclientprotocol.com/protocol/v1/cancellation), [source](https://github.com/agentclientprotocol/agent-client-protocol/blob/1c0fe8dd680aa6de119b2136a7e5495075baf257/docs/protocol/v1/cancellation.mdx#L10-L42).
- `end_turn` means the model finished responding without more tool requests. It is **not** task correctness, successful shell exit, all background jobs dead, or application-level acceptance. Lifemodel must retain its own generic semantic-result policy.

## 4. goose: tools, permissions, errors, cancellation

### Direct shell exists; code mode is not implicitly enabled

ACP's empty builtins selection defaults to **developer**. Developer defines `shell`, `write`, `edit`, `tree`, `read_image`. Developer is a **platform extension with `unprefixed_tools: true`**, so the expected direct model-facing tool in this release is **`shell`**. The extension manager adds `extension__name` only for extensions that do not expose unprefixed tools; do not assume `developer__shell` from that generic rule. Even a full build has code execution extension `default_enabled: false`. Inference tool filtering applies only when that extension is actually enabled. Published musl portable-default does not compile code-mode at all. This permits the local stub to choose from the actual model request rather than guessing a nonexistent schema.

## 5. Prime: no ACP permission handshake; tool-status path audit

The ACP directory has no request-permission method/type/handler or client capability forwarding. Its JSON-RPC Incoming enum supports only requests and notifications; a response with no method is rejected as Invalid Request. There is no outbound ACP tool-permission interaction to grant/deny in this release. This is not a violation of an optional ACP feature, but **it fails a candidate acceptance condition that requires observable permission granting/denial**. A generic client cannot add that behavior. [Parser](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/acp/jsonrpc.rs#L21-L72), [full ACP source directory](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/acp/daemon.rs).

Tool starts map to tool_call/in_progress with rawInput. Tool end mapping checks top-level `isError` (default **false**) to select failed/completed. **Path-audit correction:** main-only [`5c898d1b27b109bd2d383c68d60a30536e39cc22`](https://github.com/PrimeIntellect-ai/prime-agent/commit/5c898d1b27b109bd2d383c68d60a30536e39cc22) restores isError in the core RPC/--mode json serializer, but that serializer is **not the real daemon ACP producer**. The pinned daemon `agent_engine/turn/run_once.rs` copies is_error into EngineEvent and `worker/turn.rs` emits top-level isError before the ACP mapper consumes it. Therefore **do not attribute an observed ACP tool-error false success to that main-only serializer fix**. Runtime must test a genuinely failing model tool, not a synthetic wire event; any missing failed status still blocks acceptance, but its root cause needs separate evidence. [Core non-ACP serializer](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-core/src/session_engine/session_events.rs#L191-L201), [actual daemon engine forwarding](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/agent_engine/turn/run_once.rs#L309-L319), [actual daemon event JSON](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/worker/turn.rs#L809-L818), [ACP consumer mapping](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/acp/wire_events.rs#L130-L190).

A separate, stronger source seam is in the **actual tool bridge**: `ipython.rs` sets `ToolExecutionResult.is_error` for kernel Error/Aborted, but `tool_bridge.rs:112-113` reads that flag into a local and explicitly discards it (`let _ = is_error`) before returning `Ok(AgentToolResult { content, details, terminate: None })`. This can explain Python execution error text arriving as a completed tool even though the daemon transport correctly preserves the event flag it receives. It is not proof that every tool/error path behaves identically, nor a substitute for the real-client result. Keep the runtime symptom and complete root-cause attribution separate. [Kernel tool result](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-core/src/tools/ipython.rs#L481-L484), [flag discarded at bridge](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-core/src/session_engine/tool_bridge.rs#L108-L118).

Cancel is admission-ordered before concurrently handling requests. It marks the active turn cancelled, acquires an input pause, aborts work, cancels its owned prompt admission, waits idle, then cancels **every** RLM roster child (sequentially; every row attempted). A failed roster read or any child cancellation is a stop failure. It retains stop_failure, blocks future prompt admission, and permits retrying the stop. Original prompt response waits for cancel_task completion before leaving. [Ordering/admission](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/acp/daemon.rs#L653-L745), [cancel sequence](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/acp/daemon.rs#L800-L910), [response boundary](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/acp/daemon.rs#L1350-L1399). **These are native lifecycle operations, not an OS kill-tree guarantee.** ACP cannot prove that arbitrary detached shell descendants are gone. The isolated runtime probe must measure this.

Prime is daemon-backed **before the first ACP frame**. EOF disposes client-owned sessions (`--no-session`); resident sessions can survive. Do not assume killing the stdio child removes its detached supervisor. [Startup](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-cli/src/print_runtime.rs#L80-L120), [EOF teardown](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-daemon/src/acp/daemon.rs#L1894-L1920).

After observations, the documented cleanup command is `prime-agent shutdown --force --json`, with **the same isolated** `PRIME_AGENT_CODING_AGENT_DIR` and `PRIME_AGENT_DAEMON_SOCKET` environment values (plus PI_OFFLINE=1). Public shutdown reads the env-root; do not rely on a shutdown `--daemon-socket` argument being accepted. Rust discovery specifically scopes a pinned root to its exact socket and own agent dir, not unrelated sibling sockets. It sends native Shutdown, confirms the listener stopped, then verifies/escalates tracked residual processes under force. Never call global ambient shutdown in the owner environment. [Shutdown parser](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-cli/src/public_command.rs#L542-L552), [scoping](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-cli/src/daemon_discovery/mod.rs#L32-L43), [root resolution](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-cli/src/daemon_discovery/mod.rs#L113-L155), [native shutdown verification](https://github.com/PrimeIntellect-ai/prime-agent/blob/8aac8692456c00c01d4e53e60e6d3347a3506559/crates/pa-cli/src/daemon_discovery/stop.rs#L336-L408).

## 6. Documented startup/network controls

### goose

[Official environment guide at pinned release](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/documentation/docs/guides/environment-variables.md) documents:

- `GOOSE_PATH_ROOT`: isolated root with config/data/state subdirs; useful for hermetic probe state.
- `GOOSE_PROVIDER`, `GOOSE_MODEL`: select the actual provider and model. OpenAI implementation accepts `OPENAI_BASE_URL`, `OPENAI_HOST`, `OPENAI_BASE_PATH`, `OPENAI_API_KEY`; use loopback-only model stub and synthetic credential. [Provider config keys](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/crates/goose-providers/src/openai.rs#L715-L726).
- `GOOSE_DISABLE_SESSION_NAMING=1` or `true` (case-insensitive): disable automatic background **model** call for session naming. Guide default false.
- `GOOSE_TELEMETRY_ENABLED=false`: anonymous usage telemetry off (documented default false).
- `OTEL_SDK_DISABLED=true`: disable all OTel export; alternatively per-signal exporter `none`. Usage telemetry and OTel are separate.
- `GOOSE_DISABLE_KEYRING`: **any set value** disables system keyring (do not set `false` expecting enabled).
- `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`: documented proxy controls, not a no-egress guarantee.
- `GOOSE_MODE=approve` for permission checks; auto is the default.

**No supported runtime catalog-disable or `GOOSE_DISABLE_UPDATE_CHECK` knob was found in the reviewed startup path. Do not invent one.** Standard glibc release build uses default features, which include `online-model-meta`. Before cli dispatch, main calls `model_catalog::initialize`. That loads cache **then always spawns refresh** of `https://models.dev/api.json`. Lower-level fetch builds and sends an HTTP GET even with ETag/cache; a 304 still requires network. Telemetry/naming controls do not disable this fetch. Blocking egress does not satisfy a requirement of **no attempted startup egress**. [CLI feature defaults](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/crates/goose-cli/Cargo.toml), [main startup](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/crates/goose-cli/src/main.rs#L19-L27), [catalog initializer](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/crates/goose/src/model_catalog.rs#L5-L31), [actual HTTP GET](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/crates/goose-provider-types/src/canonical/registry.rs#L148-L162).

**Published musl variant is a legitimate different control.** Release workflow uses `--no-default-features --features portable-default` for musl, while manylinux standard build uses plain cargo build (default features). portable-default omits online-model-meta, code-mode, local-inference, system-keyring and update, while retaining bundled tools, telemetry/otel, scheduler and ACP HTTP. Therefore the musl binary should omit the unconditional catalog startup path; prove it by runtime tracing. This is an existing published release variant, not a build performed by this review. [Variant build rules](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/.github/workflows/build-cli-linux.yml#L138-L170), [portable-default exact feature list](https://github.com/aaif-goose/goose/blob/9949cf926cd42f1d128b9991ed23a496ecace896/crates/goose-cli/Cargo.toml). Other configured extensions, remote sources, model inventory refresh, docs skill fetches, or toolshim/local-model paths can still cause traffic. Empty private config and minimal builtins matter.

## 7. Existing OpenCode ACP gaps that comparisons must preserve

1. **Shell nonzero != failed ACP status.** completedToolUpdate always sets completed and includes rawOutput.metadata; core shell metadata carries exit/signal/timeout. Retain generic semantic guards for these fields and allow later agent work to recover a settled failure. Existing final-text recovery can clear an unresolved failure; a deliberately failed tool followed by fixed prose is not automatically an unrecovered-failure test. Distinguish raw failed status from the client’s accepted final outcome. [Tool mapping](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/tool.ts#L100-L147), [shell result](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/core/src/shell/result.ts#L30-L42).
2. **Prompt cancellation is not whole-family termination.** Adapter interrupts session, drains events for a configurable default five seconds, then marks remaining calls abandoned if necessary. Child agents may explicitly **outlive** a cancelled turn; the adapter follows their permission asks in background. Thus cancelled alone does not prove no descendants remain. [Timeout](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/turn.ts#L32-L42), [windDown](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/turn.ts#L261-L278), [children outlive](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/turn.ts#L299-L311).
3. **Permission callback must always settle.** Options are once/always/reject with standard allow_once/allow_always/reject_once kinds. Unknown/cancelled choice becomes reject. [Permission](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/permission.ts#L42-L83).
4. **Provider errors are correctly distinguished from ordinary end_turn in this baseline.** Auth failures -> AuthRequiredError; other non-abort/non-content-filter failures -> service failure. Refusal/max_tokens/cancelled are explicit. A candidate that streams an ordinary provider error as text plus end_turn has a raw semantic defect, not equivalent raw ACP semantics. The lifemodel relay may separately report a provider error and protect the real client; measure raw ACP and protected client outcomes separately. [Failure](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/translate.ts#L137-L166), [stop reason](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/translate.ts#L470-L478).
5. **No standard same-turn steer contract.** Prompt admission rejects another turn for same session; task steer/wrap ACK remains launcher policy. Do not invent a native side channel or assume cancel+new prompt proves uninterrupted steering. [Admission](https://github.com/anomalyco/opencode/blob/68bc26b7da1990ce10ffecfbc1e09eb13aa5d824/packages/cli/src/acp/turn.ts#L374-L396).

## 9. Bounded runtime-evidence audit (read-only, parent-owned runs)

After the source review, this lane read the parent's probe scripts and receipts. It did not run candidates or change those files. The final `runs/goose-musl-cancel-raw/result.json` records startMarker plus both shell/child live **at cancel**, then child `(sleep) S` with PPID 1 at cancelled prompt return and two seconds later, with the same process starttime. The agent remains alive through the observation window. That is a real live orphan, not a zombie or cleanup artifact. `completionMarker: false` alone would not prove child termination, because killing the waiting shell prevents the final touch while its child can remain alive. The comparable Prime receipt records both live at cancel and absent at return and two seconds later; native daemon cleanup runs only after observation. These are bounded observations for this command, not universal process-tree guarantees.

The run labeled `goose-musl-cancel-no-notification-invalid` sent no cancellation and cannot support a cancellation claim. Earlier shell-only cases do not prove descendant cleanup. Current scripts explicitly record notification timing and pre-notification liveness. Raw permission approval selects the offered allow_once option and creates the tool marker; cancelled permission denies it and leaves the marker absent. The stub's fixed final prose deliberately does not verify task correctness. Therefore real-client success following failed tools or permission denial must be read under the existing final-text recovery policy, not treated as isolated proof of a new adapter defect. Parent runtime report owns archive checksums, complete result matrix, final gate verdict, and paths to retained receipts.
