# Native steering probe reproduction

Research only. Read [../task-steering.md](../task-steering.md) first. Nothing
here is a production adapter. Run from repository root. Needs Docker, Python 3,
Node.js and `lifemodel-heavy`. Heavy work is serialized; do not parallelize it.
Fresh outputs refuse overwrite. No owner key/config is read.

## Build and run

1. `python3 docs/research/task-steering/fetch.py` downloads and verifies the
   previous probe's published Prime archive pin, and downloads the cited
   OpenCode source for inspection. Source is never built.
2. Build the existing workbench, then reuse the previous Prime overlay:

   ```sh
   lifemodel-heavy docker build -f docker/workbench/Dockerfile -t probe-6539-2/workbench:stock .
   lifemodel-heavy docker build --build-arg BASE=probe-6539-2/workbench:stock -f docs/research/task-harness-acp/Dockerfile.probe -t probe-6539-2/prime:0.10.1 docs/research/task-steering/artifacts
   lifemodel-heavy docker build -f docs/research/task-steering/Dockerfile.probe -t probe-6539-2/steering:probe docs/research/task-steering
   ```

3. Generate probe-only TLS material, not an owner certificate or key:

   ```sh
   openssl req -x509 -newkey rsa:2048 -nodes -keyout docs/research/task-steering/artifacts/stub.key -out docs/research/task-steering/artifacts/stub.crt -days 7 -subj /CN=127.0.0.1 -addext subjectAltName=IP:127.0.0.1
   chmod 644 docs/research/task-steering/artifacts/stub.key
   python3 -c "from pathlib import Path; Path('docs/research/task-steering/artifacts/token').write_text('probe-placeholder-only')"
   ```

   The private key is generated, ignored and never committed. It is world-readable
   only so UID1000 can use this disposable test certificate.
4. `python3 docs/research/task-steering/run-all.py` runs 12 containers one at a
   time, each network-none with a fresh task home. `run-local.py` captures the
   exact Docker command and its own exit status. The timeout starts after the
   heavy-work lock. A failed run removes its named container. Containers are
   labelled `com.lifemodel.probe=6539-2` and named `probe-6539-2-*`.
5. For a single case:

   ```sh
   python3 docs/research/task-steering/run-local.py opencode late --name custom-opencode-late
   python3 docs/research/task-steering/run-local.py prime-agent compact --name custom-prime-compact
   ```

6. The retained `evidence/` already exists in this commit. To rebuild it, first
   move it aside **within this worktree**, then preserve build/image receipts
   there. `collect-evidence.py` copies only `runs/final-*` and refuses an existing
   case directory. Then run `node docs/research/task-steering/verify-evidence.mjs`.
   A verifier success requires Prime's known negative observer result; it does
   **not** turn Prime into a passing candidate.
7. Remove only the named probe containers and the three `probe-6539-2/*` images
   after capturing evidence. Never prune shared images or caches.

## Files

- `run.mjs`: native clients, same standard ACP driver as the previous probe,
  private config, completion timelines, status/history inspection.
- `stub.mjs`: TLS scripted provider, raw request-body log, real tool schema
  selection, final-stream barrier and compaction replies. It never inserts
  steering into requests. Only copies a marker into a summary when its input
  contains that marker.
- `plugin/`: baked OpenCode v2 local plugin. Unix input calls native
  `ctx.session.prompt`; live native events track pending/promoted input.
- `Dockerfile.probe`: plugin-only overlay over the previous pinned Prime runtime.
- `run-all.py`, `run-local.py`: serial orchestration / bounded disposable boundary.
- `collect-evidence.py`, `verify-evidence.mjs`: evidence collection and assertions.
- `pins.json`, `*-source-notes.md`: pins and source qualifications.
- `evidence/`: all 12 final runs. Raw model bodies are the primary evidence;
  result summaries are not enough. System prompts are generated by each pinned
  agent in a fresh private home, not copied owner settings. Native hello logging
  keeps only version/protocol/build/PID fields, not supervisor ownership tokens.

## Important qualifications

Prime's Python `bash()` default await yields a live snapshot at 10 seconds;
this probe sets `yield_after=60` for its 20-second tool. Two Python calls are
serial in this configuration. Prime automatic compaction requires a genuinely
discardable history prefix, not only large reported usage. The compact case
uses padded initial text plus padded tool results and a second tool round.
OpenCode's compaction command is queued only after native steering was inserted.
Neither manual Prime compaction nor a second RPC engine is used in final runs.

The two-second post-terminal observer is bounded. `tail` holds a final stream
before its stop frame; `late` admits directly after the terminal reply. The
latter deliberately demonstrates Prime's unowned successor, while OpenCode
leaves input pending. Lost-ACK is modeled by replaying the same ID, not by
forcibly breaking sockets. The third duplicate replay occurs after promotion.
OpenCode's live event map is volatile; production restart reconciliation is
not implemented. ACP terminal/cancel/permission semantics from the older probe
remain separate findings.
